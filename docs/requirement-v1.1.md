### 4.3 ✏️ Thread 默认态（混合态 C · v1.1 重写）

**v1.0 方案的问题**：所有 Thread 默认收起 → 打开 Event 只看到一堆标题 → 讨论氛围被"藏"起来 → 新人错过 → 评论区从"吵闹"变成"冷清"——这不是升级，是倒退。

**v1.1 方案**：**混合态 C · 保留最活跃信号**

#### 4.3.1 Thread 三态

| 态 | 判定 | 默认可见 | 展开方式 |
|---|---|---|---|
| **活跃** | ≤3 天内有新回复 | 首条消息完整 + **最新 1 条回复** + 折叠条 | 点折叠条 → 展示全部历史 |
| **冷态**（cold） | >3 天无新回复 | 首条消息 + 头部 🧊 冷 标 | 点卡片 → 整体展开 |
| **已解决**（resolved） | 被手动标记 | 首条消息 + 头部 ✓ 已解决标（绿色）+ 整体半透明 | hover → 显示"撤销已解决"小链；点卡片 → 整体展开查看历史 |

#### 4.3.2 折叠条设计

```
─── ▾ 查看 N 条历史回复 ───
```

- 位置：首条消息 与 "最新 1 条回复" **之间**
- 视觉：11.5px + 浅灰 #9ca3af + 细虚线
- 交互：点击展开所有历史；再点收起；箭头 180° 翻转动效

#### 4.3.3 为什么是"首条 + 最新 1 条"，不是"首条 + 最新 N 条"

- **最新 1 条** = 讨论的当前状态（往往是总结 / 结论 / 最新进展）
- **首条** = 讨论的缘起（让新人能理解议题）
- **中间流水账** = 低价值，折起来反而提升信噪比
- 参考：飞书文档评论 / Gmail 对话折叠的成熟模式

#### 4.3.4 边界场景

- **0 回复**：只显示首条消息 + "💬 暂无回复，首个回复 →"（直接聚焦回复框）
- **1 回复**：首条 + 回复都直接展示，不出现折叠条
- **2 回复**：首条 + 折叠条（"查看 1 条历史"）+ 最新 1 条
- **N ≥ 3 回复**：首条 + 折叠条（"查看 N-1 条历史"）+ 最新 1 条

#### 4.4.5 🆕 My 待办跟踪（跨 Topic 聚合）

**问题**：v1.0 里用户只能在 **单个 Event 内部** 看到相关待办——意味着：
- 嘉辉被指派了 3 个 Topic 下的待办，他需要跨 3 个 Event 才能看全
- 肖迈发出了待办，他压根没地方跟踪谁完成了、谁逾期了
- 既不符合"透明即生产力"，也让"讨论转待办"这个能力打了折扣

**方案**：新增 My 页面下的 `待办跟踪` 子模块，提供双视角。

##### 两种视角

| 视角 | 用户画像 | 内容 |
|---|---|---|
| **我的待办**（被指派） | 任何被别人从讨论里转来的待办；或自己从讨论里转给自己的 | 跨所有 Topic 聚合 |
| **我发出的**（指派他人） | 我把讨论转成待办指派给他人 | 跨所有 Topic 聚合 |

##### 字段要求

| 字段 | 我的待办 | 我发出的 |
|---|---|---|
| 内容 | ✅ | ✅ |
| 来源（→ 原讨论的深链） | ✅ | ✅ |
| 指派自/给谁（头像+姓名） | ✅ | ✅ |
| 截止日期 + 紧迫度色标 | ✅ | ✅ |
| 状态（待处理/已完成/逾期） | ✅ | ✅ |
| 完成时间 | ✅（完成后） | ✅ |
| 逾期天数标红 | ✅ | ✅ |

##### 筛选 Tab

`全部 · 待处理 · 已完成 · 逾期` —— 每个 Tab 右侧带计数。

##### AI 参谋条（引用 v1.2 规划）

- 我的待办视角："你有 N 条逾期，N 条 3 日内到期，建议优先处理。" + "让 AI 起草延期说明"
- 我发出的视角："本周指派 N 条，完成 N 条，XX 的任务已处理 N 天" + "让 AI 代发催办私信"

##### 入口位置

- 侧栏 `MY` 下增加一个子项：`📋 我的待办`
- My 主页面顶部的"待办数"可以直接点进来

### 4.7 🆕 Thread 标记为已解决（v1.1 新增）

#### 4.7.1 为什么要这个功能

**"转为待办"和"标记已解决"是两种不同的闭环**：

| 情境 | 正确动作 |
|---|---|
| 讨论有具体可执行的事情 → 谁去做 | **📌 转为待办** |
| 讨论已得出结论，**不需要再继续追** | **✓ 标记已解决** |
| 讨论跑题 / 无共识 / 无下文 | （保持 `⏳ 等待回复中`，让冷 Thread 自然沉底） |

很多讨论（共识型、答疑型、澄清型）根本不需要变成任务——只需要一个"已归档"的语义标记，让大家知道这题过了。

#### 4.7.2 操作入口

- **Thread 卡片头部** 右上角的 `···` 菜单（**Thread 级**，不是 Reply 级）
- 菜单项：`✓ 标记已解决` / `📍 置顶到讨论区` / `🔔 订阅 / 取消` / `🔗 复制链接` / `🗑️ 删除讨论`（danger）

#### 4.7.3 交互效果

| 时刻 | 效果 |
|---|---|
| 点击"标记已解决" | ① Thread 整体半透明（opacity 0.88）<br>② 头部右侧出现绿色 `✓ 已解决` 胶囊标<br>③ Thread 内部自动插入系统消息 `─── ✓ 讨论已标记为已解决 · 刚刚 ───`<br>④ 默认整体折叠（点卡片可展开查看来龙去脉） |
| Hover 已解决 Thread | 头部时间戳旁出现"撤销已解决"小链（虚线下划） |
| 撤销已解决 | ① 恢复正常态<br>② 移除胶囊标<br>③ 移除本次添加的系统消息<br>④ toast："已撤销 · 讨论重新激活" |

#### 4.7.4 权限

- Thread 发起者 **始终**可以标记/撤销自己的 Thread
- Event 维护者 **始终**可以标记/撤销 Event 下任意 Thread
- 其他 Thread 参与者 **可以**标记，但**不能**撤销他人的"已解决"标记

#### 4.7.5 副作用

| 维度 | 效果 |
|---|---|
| 通知 | 标记已解决 → Thread 所有参与者收到一条轻量通知（仅站内，不发 Bot） |
| AI 总结 | 已解决 Thread 优先作为"已有结论"输入 AI 总结 |
| 搜索 | 已解决 Thread **不降权**，但搜索结果会带 `✓ 已解决` 标，帮助判断 |
| 统计 | Topic 动态/简报里可以看到"本周 X 条讨论已解决"作为活跃指标之一 |

### 4.8 🆕 输入提交键位规范（v1.1 新增）

#### 4.8.1 为什么要统一

v1.0 的输入框用户要么不知道怎么发（发送按钮视线远）、要么用惯了 IM 的 "Enter = 发送" 却 preview 出换行——**心理门槛和反直觉**。讨论氛围的敌人就是"我该怎么发一条？"的摩擦。

#### 4.8.2 键位规范

**核心原则：Enter 即发布，⌘↵（Ctrl+Enter）换行。**

| 键位 | 行为 | 说明 |
|---|---|---|
| `Enter` | **发送** | 主发送键；与 IM 习惯一致 |
| `Shift + Enter` | 换行 | 保留兼容（老 IM 用户肌肉记忆） |
| `⌘ + Enter` / `Ctrl + Enter` | 换行 | **主要换行键**（对齐 Slack / Linear） |
| IME 组字中 `Enter` | 选字（不发送） | 通过 `isComposing` / `keyCode 229` 识别 |

#### 4.8.3 视觉提示

| 位置 | 提示形式 |
|---|---|
| 输入框 `placeholder` | `发起讨论... Enter 发送 · ⌘ Enter 换行` |
| 输入框下方 `.nt-hint` | `提示：输入 <kbd>@</kbd> 提及 · <kbd>Enter</kbd> 发送 · <kbd>⌘ Enter</kbd> 换行` |
| 空态 | 同样带键位提示，让新人一眼知道怎么发 |

#### 4.8.4 实现规范

- **所有可发送的输入区**（发起 Thread / 回复 Thread / 评论迁移的兜底）**必须**走统一的 `handleSubmitKey(ev, onSubmit)` 函数
- 单行输入（input）**不建议**直接支持 ⌘↵ 换行（升级为 toast 提示"需多行请展开"），或者升级成单行态的 textarea（视觉单行，可扩展）
- 多行输入（textarea）**必须**响应 ⌘↵ / Ctrl↵ / Shift↵ 三者之一插入 `\n`
- 跨平台：用 `e.metaKey || e.ctrlKey` 识别，不依赖 navigator.platform

#### 4.8.5 回归影响

| 现有功能 | 是否受影响 |
|---|---|
| @ 提及选择面板 | ❌ 不受影响（Enter 选中当前高亮项，优先级 > 发送） |
| 富文本引用 / 附件 | ❌ 不受影响（引用插入后光标留在正文，继续适用本规则） |
| IME 中文输入 | ✅ 已处理（isComposing 检测） |

## 五、交互流程（v1.1 增补）

除了 v1.0 §5 的 6 步闭环外，新增两条典型路径：

### 5.A Thread "已解决" 路径

```
Step 1 · 讨论成熟
  - 3 个人在 Thread 里来回 5 轮，达成共识，无需进一步动作

Step 2 · 标记
  - 肖迈（维护者）点 Thread 头部 ··· → ✓ 标记已解决
  - Thread 变半透明，头部加绿色胶囊标，内部插系统消息

Step 3 · 归档态
  - 新人进 Event 不会被"噪声"干扰（视觉上已弱化）
  - AI 总结优先引用已解决 Thread 的结论

Step 4 · 发生后续
  - 若议题再起波澜，参与者可 hover 点"撤销已解决"→ 回到活跃态
```

### 5.B 被指派人跨 Topic 追踪路径

```
Step 1 · 接到多个任务
  - 嘉辉：周一收到 3 个不同 Topic 的 @ 指派通知

Step 2 · 聚合查看
  - 嘉辉点侧栏 MY → 我的待办（跨 Topic 聚合视图）
  - 按"待处理 / 逾期"筛，优先处理红色逾期条

Step 3 · 跳转原讨论
  - 点任意待办的"来自讨论 · [链接]"chip
  - 直接跳回原 Thread 并高亮定位到指派消息

Step 4 · 完成勾选
  - 在待办列表直接勾选 → 触发 §4.5.2 +1 规则
  - 原指派人收到"xx 已完成"通知
  - 原 Thread 自动插入系统消息"✓ xx 已完成关联待办"
```

## 附录 B · AI 在 Thread 中的角色（v1.2 规划）

> 本节是 2026-05-05 讨论的沉淀。v1.1 **暂不实现**这些能力，但文档先记录，作为 v1.2 候选。

### B.1 5 个候选能力

| # | 能力 | 场景 | 实现复杂度 |
|---|---|---|---|
| B1 | **AI 看到讨论陷入循环，主动跳出来**："要不要我总结下大家说的几个核心点？" | Thread 回复 >8 条、2 小时内无进展时触发 | 中 |
| B2 | **AI 作为第四发言者**，帮补证据/反驳/提炼 | 用户在 Thread 回复框输入 `/ai 帮我补证据` | 高 |
| B3 | **每个 Thread 顶部"共识进度条"**（AI 判断共识达成程度） | 所有 >3 回复的 Thread 常驻显示 | 高 |
| B4 | **@AI 命令**：`@AI 帮我总结这个 Thread` / `@AI 起草回复` | 用户主动召唤 | 中 |
| B5 | **AI 防重复讨论**：提示"这议题上周在 xx Topic 已讨论过" | 新 Thread 发起时自动检测 | 中 |

### B.2 v1.2 规划优先级（待决策）

**建议优先级**：
1. **B4（@AI 命令）** —— 最轻、最易落地、最不打扰
2. **B5（防重复）** —— 高价值，是"Nexus 独门护城河"的体现
3. **B1（循环提醒）** —— 中等价值，但触发时机需精调
4. **B3（共识进度条）** —— 很酷，但可能"过度 AI"
5. **B2（AI 发言者）** —— 最大胆，需谨慎（避免 AI 抢戏）

### B.3 设计原则

1. **AI 必须可关**（每个 Thread 右上角可开关"AI 参与"）
2. **AI 发言必须有明确标识**（头像+姓名+金框）
3. **AI 不主动删除人的内容**
4. **AI 的总结有"AI 生成"标签**，便于审查
5. **用户永远有最终决策权**（AI 的转待办建议要人确认）
