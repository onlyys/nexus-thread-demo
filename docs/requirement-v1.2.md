## 0. 版本定位（本版本的"宪法"）

### 0.1 Nexus 产品边界

| 维度 | 定位 |
|---|---|
| **是什么** | **信息透明 · 信息呈现 · AI 辅助信息呈现 · 协助决策** |
| **不是什么** | **不是研发辅助工具**（不对标 Linear / Jira / GitHub / Asana） |

**这条边界决定了 v1.2 的每一次取舍。**  
当某个功能/视觉让人联想到"任务管理 / 工单系统"时，就是偏离了主轴。

### 0.2 概念边界

全站只有两个核心概念：

| 概念 | 是什么 |
|---|---|
| **Topic** | 一条产品线、一个项目方向，是长期的"容器" |
| **Event** | Topic 下的一次发布、一次动态、一次长段落正文 |

**⚠️ v1.1 引入的 "Thread"（话题束）概念 → v1.2 撤销。**  
Thread 让用户产生"这是任务堆"的误判，与信息呈现主轴冲突。

### 0.3 讨论在哪一层

讨论依附于 **Event**。进入一个 Event 的正文页，下方就是该 Event 的讨论区。**不做跨 Event 的"讨论空间"**。

## 1. 背景与目标

### 1.1 v1.1 的误判（必须认真复盘）

v1.1 把 Event 里的多条发言结构化成"Thread（话题束）"：
- 每个 Thread 是一个白底卡片 + 边框 + 圆角
- Thread 头部显示状态 chip：`💬 N 条回复` / `✅ 已转为待办` / `⏳ 等待回复中`
- Thread 默认态用混合态 C（首条+最新可见，中间折叠）
- 支持在 Thread 级别 `📌 转为待办` / `✓ 标记已解决`
- 独立的"My 待办"跟踪场景

**真实用户反馈（Wang 访谈 4 位活跃用户后）：**
> "我点进去看到一堆白底卡片，不太确定是评论还是任务。"

**这条反馈决定了 v1.2 的全部方向：**
- Thread 概念撤销
- 视觉降噪
- 不借用任何任务管理系统的表达（状态 chip、指派人、截止日期 … 一律剔除到用户视线之外）

### 1.2 v1.2 的四个具体目标

1. **概念回归** · 不再使用 Thread，讨论区回归一条条发言的扁平形态
2. **视觉降噪** · 用户注意力集中在 **"讲了什么"**，而不是状态 chip / 卡片框 / meta 信息
3. **参与门槛降低** · 输入入口置顶 + 邀请式文案，让"说一句"变得轻松
4. **轻量流转** · 通过 @ + 「来看」列表让信息在人与人之间流动，**不是任务分派**

## 2. 核心改动

### 2.1 信息架构调整

| 层 | v1.1 | v1.2 |
|---|---|---|
| Topic | ✅ 保留 | ✅ 保留 |
| Event | ✅ 保留 | ✅ 保留 |
| **Thread** | ✅ 有 | ❌ **移除** |
| 讨论 → 回复 → 子回复 | Thread 内部结构 | **直接挂在 Event 下，树形层级** |

### 2.2 讨论区视觉重构 ⭐ 重点

#### 2.2.1 三层字号梯度

让"Event 大、首条次之、回复再小"的层级感通过字号本身传递，不依赖边框/底色。

| 层级 | 字号 / 行高 | 字重 | 说明 |
|---|---|---|---|
| Event 标题 | **26px / 1.3** | 600 | 最显眼 |
| Event 正文 | **15.5px / 1.85** | 400 | 阅读感最佳 |
| 首条 author | 14.5px | 600 | 讨论起点的署名 |
| 首条 text | 15px / 1.75 | 500 | **text 比 author 大 + 加粗**，让讨论起点有分量 |
| 回复 author | 13.5px | 600 | |
| 回复 text | 14px / 1.7 | 400 | |
| 子回复 author | 12.5px | 600 | |
| 子回复 text | 13.5px / 1.65 | 400 | |
| 作者【中文名】 | 比 author 小 2px | 400 · `#9ca3af` | 辅助识别 |

#### 2.2.2 作者署名格式

```
Brant 【钟嘉辉】          Wang 【王昕】          Xiaomai 【肖迈】
```

- 英文 ID 为主（黑色加粗）
- `【中文名】` 为辅（灰色小字）
- **不再显示部门角色**（~~`· 技术架构`~~ / ~~`· SSV 产品`~~）

#### 2.2.3 Meta 信息处理

| v1.1 有的 Meta | v1.2 处理 |
|---|---|
| `💬 4 条回复` | ❌ 移除 |
| `✅ 已转为待办` | ❌ 移除 |
| `⏳ 等待回复中` | ❌ 移除 |
| `最新：肖迈 · 30 分钟前` | ❌ 移除 |
| 每条发言的时间戳 | 🔶 默认隐藏，hover 头像才显 |
| 发言人部门 | ❌ 移除（见 2.2.2） |

#### 2.2.4 树形结构：主线 + T 字分叉

**参考：GitHub PR 评论树**

```
[Brant·钟嘉辉]  ← 首条
       ╲
        ┃ ← 主竖线从首条头像中线下来
        ├──[Wang]
        ┃
        ├──[Danyang]  
        ┃
        ├──[Peilun]
        ┃
        └──[Xiaomai]  ← 末端在 T 字处收束
              ╲
               ┃ ← 子回复线从父 body 内继续下来
               └──[Brant · 子回复]
```

**技术参数：**
- 竖线：`2px solid #e6e8eb`
- T 字横画：22px 长
- 模块内首条缩进：0
- 回复缩进：37px（T 字横画 22px + 小 gap）
- 子回复相对父回复再缩进：22px
- 首条头像：38px
- 回复头像：30px
- 子回复头像：26px

#### 2.2.5 模块间距

- 每个"首条"开启一个独立模块
- 模块之间：**48px 间距 + 1px `#f1f3f5` 横线**
- 依据：4px 网格系统的 12 倍 = 48px，远大于模块内最大间距（18px 回复段间距），保证视觉可分

### 2.3 发起讨论框置顶（X 风格）

**位置**：讨论区最顶（`Event 正文` 之后、`第一条讨论` 之前）

**视觉：**
- 白底（不再是灰色，避免"不可点击"的错觉）
- `1.5px dashed #c7d2fe` 浅蓝虚线边框
- 左上角浮动徽标：`✨ 加入讨论`
- hover：边框中蓝 + 微泛蓝底
- focus：实线蓝色边框 + 4px 蓝色光晕（明确告诉用户"可以打字"）

**文案：**
- placeholder：`我也来参加讨论…`
- 工具条：`@` `🔗` `📎` `🖼` + 发起按钮
- **不显示键位提示**（Enter 发送 / Shift+Enter 换行代码内生效，UI 纯净）

### 2.4 富内容（降权，不抢焦点）

| 类型 | v1.2 方案 |
|---|---|
| **@ 人** | 纯蓝字 `#2563eb`，**无底色**；hover 下划线；输入 `@` 触发浮选人面板 |
| **链接** | 蓝字 + 极淡下划线 `#dbeafe`；hover 下划线变中蓝 `#93c5fd` |
| **图片** | 240×130 浅灰占位卡（`#fafbfc` 底 / `#e6e8eb` 边），点击全屏 lightbox |
| **文件** | **Inline 风格**：`📄 文件名.pdf · 1.2 MB`，虚线下划线；hover 变蓝；**不做卡片** |

**设计原则**：富内容永远不能比"讲了什么"更抢眼。

### 2.5 消息操作（点赞 / 转待办 / 更多）

**入口**：hover 整条发言 → 右上角浮出白色操作条

**三个按钮**：

| 按钮 | 功能 | 激活态 |
|---|---|---|
| 👍 | 点赞（可反向取消），实时显示计数 | `#fff7ed` 浅橙底 + 橙字 |
| 📌 | 转为待办 | 蓝色高亮 |
| ⋯ | 更多：标记已解决 · 复制链接 · 引用 · 举报 | — |

**视觉参数：**
- 浮层：白底 + `1px solid #e6e8eb` + `border-radius: 8px` + 极淡阴影
- hover 全条发言触发，`opacity: 0 → 1` + `translateY(-2px) → 0` 过渡 150ms
- 不占用 layout 空间（`position: absolute`），不抢内容焦点

**为什么这么设计（vs v1.1）：**
- v1.1 把状态 chip（✅ 已转为待办）直接挂在 Thread 卡片上 → 抢戏
- v1.2 让操作回归"功能按钮"本分，只在用户有交互意图时浮出

### 2.6 @ 驱动的「来看」列表（替代 v1.1 My 待办）

#### 2.6.1 逻辑

```
有人发言 → @某人
    ↓
被 @ 的人「来看」列表 +1 条
    ↓
┌─ 被 @ 的人进入 → 发言了 → 自动移出「来看」（闭环）
└─ 被 @ 的人进入 → 没发言 → 继续留在列表里
```

#### 2.6.2 核心原则

- ❌ 不是任务派发，✅ 是**信息请求**
- 闭环信号 = **发言有输出**，不是"点击已读"
- 无"指派人"、"截止日期"、"状态流转" 等任务管理概念

#### 2.6.3 决策（已定）

| 问题 | 决策 |
|---|---|
| 被 @ 的人"回复了但只说『收到/好的』"算不算闭环？ | **✅ 一律算闭环**（简单优先，不做内容判断） |
| 被 @ 多次 | 列表合并为一条（显示计数 +N） |
| @ 所有人 (@all) | 不进入 @ 列表（避免骚扰） |

#### 2.6.4 UI 入口

左侧 sidebar "MY · 来看" 分段：
- `@ 有人 @ 我看` · 显示未闭环数量
- `我参与的` · 我 follow 的讨论

### 2.7 AI 总结右栏（沿用 v1.1 v1.2 精神）

保留，但升级内容结构：

| 分区 | 内容 |
|---|---|
| **话题 1 · XX** | 分歧 / 结论 / 行动项 |
| **话题 2 · XX** | 关键判断 / 行动项 |
| … | |

- 每个"话题"对应讨论区一个首条模块
- 状态徽标只有两种：`已收敛` / `进行中`
- 底部有 `↻ 重新生成` 按钮

## 3. 文案全站审查（§2.1 兑现）

### 3.1 原则

- **降低门槛** > 准确描述
- **邀请** > 命令
- 去除任何任务管理词汇

### 3.2 改动点

| 位置 | v1.1 | v1.2 | 理由 |
|---|---|---|---|
| 讨论区标题 | `💬 讨论区` | `💬 讨论` · 右侧小计数 | 省一个字 |
| 发起讨论 placeholder | `发起讨论… 输入 @ 可提及同事，Enter 发送，⌘ Enter 换行` | `我也来参加讨论…` | 邀请 + 简短 |
| 发起按钮 | `发起讨论` | `发起` | 按钮自带上下文 |
| Event meta | `xx 评论了你的 Event` | `xx 在 Event 下发言` | 更轻 |
| 被 @ 通知 | `xx @ 了你，请处理` | `xx @ 你来看` | 非命令式 |

| 空态 | `还没有人发起讨论，来开启第一条` | `还没有人说话，说点什么？` | 拟人化、轻 |

## 4. 技术实现要点

### 4.1 数据模型

```
Message (一条发言)
├── id
├── event_id        (挂在哪个 Event 下)
├── parent_id       (null = 首条；非 null = 回复某条)
├── author_id
├── content         (富文本)
├── mentions        (user_id[])
├── attachments     ({type, url, size, name}[])
├── reactions       ({type, user_id[]}[])  — 点赞等
├── actions         ({type, status}[])     — 转待办 / 已解决
└── created_at

UserWatchList (「来看」列表)
├── user_id         (被 @ 的人)
├── message_id      (触发 @ 的那条)
├── mentioned_at
└── closed_at       (null = 未闭环；非 null = 用户已发言)
```

**关键点**：
- 讨论结构完全由 `parent_id` 决定，**无 Thread 表**
- 「来看」列表是**派生视图**，不是业务实体

### 4.2 渲染规则

- 层级计算：`parent_id = null` → lead；`parent_id = lead.id` → reply；`parent_id = reply.id` → sub-reply
- 暂不支持超过 2 层深度（sub-reply 下不能再 sub-reply），避免无限深树
- 如果用户试图回复子回复：默认回复到**同级**（即回复该子回复的父回复）

### 4.3 闭环判定

```
onMessageCreate(msg):
  for each mention_id in msg.mentions_in_parent_chain():
    closeWatchItem(user=mention_id, trigger_msg=msg.parent_root_id)
```

**即**：用户在被 @ 的那条讨论树下的任何位置发言，都算闭环。

### 4.4 字号 / 间距基础系统

| token | 值 |
|---|---|
| `--font-size-lead-text` | 15px |
| `--font-size-lead-author` | 14.5px |
| `--font-size-reply-text` | 14px |
| `--font-size-reply-author` | 13.5px |
| `--font-size-sub-text` | 13.5px |
| `--font-size-sub-author` | 12.5px |
| `--line-height-body` | 1.7 |
| `--spacing-module` | 48px |
| `--spacing-reply` | 18px |
| `--color-tree-line` | `#e6e8eb` |
| `--color-tree-line-width` | 2px |
