## 一、善擎是什么

**善擎 = SSV 社会价值智能赋能平台**

核心公式：`SQI 评估框架 + 多源数据统一层 + AI 安全代理 + 四级权限体系 + MCP 对外接入`

核心理念：**数据不出域，知识可输出。**

### 产品定位
- 对内：统一 SSV 各业务线（公益/乡村/应急/捐赠）的数据，建立标准化 SQI 评估体系，让管理层看得到全局
- 对外：通过 MCP 协议，让外部（政府/企业/NGO）用自己的 AI 工具接入 SSV 的行业洞察，但原始数据不出域

### SQI 评估体系
- **S - Scale/规模**：覆盖人数、地域范围、项目数量、资源投入
- **Q - Quality/质量**：执行达标率、流程规范度、用户满意度、合作方评价
- **I - Impact/影响力**：社会效益指标、长期改变、可持续性、行业影响

> 财务数据是所有维度的底层支撑。

## 二、系统架构核心概念

### 四层架构
1. **用户接入层** → 四级用户（L4高管/L3业务/L2内部/L1外部）
2. **AI Agent 安全代理层** → 权限网关 + 检索引擎 + 输出转化器 + 安全审核
3. **AI 能力层**（私有化部署）→ 智能问答 Copilot / 方案生成器 / SQI 评估引擎 / 数据洞察分析
4. **数据统一层** → 联邦查询网关 → 公益DB/乡村DB/应急DB/捐赠回收库/财务层/知识资产库

### A/B 双循环机制
- **B 端（对外）**：外部用户通过 MCP 提问 → AI 返回行业洞察 → 暴露数据缺口
- **A 端（对内）**：被 B 端倒逼 → 数据统一层建设 / SQI 标准化 / 数据回收 → 知识资产越来越完整 → B 端输出更好

### 四级权限模型

| 等级 | 角色 | 数据可见范围 | AI 输出方式 |
|------|------|-------------|------------|
| L4 高管 | VP 及以上 | 全量数据含财务 | 直接输出原始数据+分析 |
| L3 业务 | 业务线授权人员 | 本线全量，跨线公开 | 本线直接，跨线脱敏 |
| L2 内部 | 普通员工 | 仅公开信息 | 只输出公开信息 |
| L1 外部 | 政府/企业/NGO | 公开信息+AI加工洞察 | 不披露数据，转化为行业洞察 |

## 三、AI 能力层设计（重点参考）

善擎的 AI 能力层包含四个引擎：

### 3.1 SSV 智能问答 Copilot
- RAG 知识检索（200+标杆案例 + 30+ SOP + 政策法规）
- 多轮对话 + 工具调用 + 来源标注
- **权限感知**：同一个问题，根据用户 L1-L4 返回不同深度的回答

### 3.2 智能方案生成器
- 基于已验证项目模式的方案自动组合和生成
- 输入需求描述 → 匹配类似成功案例 → 组合生成可行方案

### 3.3 SQI 评估引擎
- S/Q/I 三维自动评分
- 跨项目对标分析
- 影响力报告自动生成
- 数据完整度监控（哪些项目的 SQI 还缺什么数据）

### 3.4 数据洞察分析引擎
- 趋势预测
- 对标分析
- **异常预警**（SQI 下滑 / 数据逾期 / 预算异常）
- 一键汇报生成

### AI Agent 安全代理层的输出转化逻辑
示例：外部用户问"我想做乡村教育项目，大概投入多少？"
1. 权限网关 → 确认 L1 外部用户
2. 检索引擎 → 读取 SSV 多个乡村教育项目财务数据
3. 计算均值和范围
4. 输出转化器 → L1 规则：不输出原始数字，转化为行业洞察
5. 返回："根据行业实践，同类项目通常需要投入 XX-XX 万元…"

### 技术栈
- DeepSeek-V3.2（主力推理，8×A100 80G）
- Gemma 4 26B/31B（Agent 调度 + 工具调用，1×A100 80G）
- vLLM / SGLang 推理框架
- Milvus / 腾讯云向量 DB + BGE/M3E Embedding
- MCP Server 对外接入

## 四、数据层架构（10 个数据源）

### 4.1 项目管理数据（已有系统）
- **项目数据库**：5 种立项类型，覆盖全生命周期
- **业务管理系统**：含项目结项数据
- **财务数据层**：已有，所有 SQI 维度底层支撑

### 4.2 自研项目运营数据（已有，各自独立）
- 公益数据库、乡村数据库、数字教育数据库
- 现状：三大业务线各自独立分散

### 4.3 影响力与研究数据
- **影响力素材库**：ssv.tencent.com/case + 新闻稿 + 社媒
- **研究案例库**：学术/行业研究资料

### 4.4 外部回传与知识资产
- **捐赠数据回收库**（需新建）：各合作方回传格式不统一
- **知识资产库**：标杆案例 200+ / SOP 30+ / 政策法规 / 行业报告

### 数据统一三阶段
1. Phase 1（M1-6）：联邦查询，各库不动只做查询路由
2. Phase 2（M7-12）：数据湖（Iceberg/Hudi），支持复杂分析
3. Phase 3（M13-24）：全面迁移到统一数据模型

## 五、产品界面矩阵

### L4 VP 驾驶舱
- 顶部：4 个数据卡片（项目总数/总投入/总覆盖/SQI 均分）
- 中部：SQI 业务线热力图 + 投入产出趋势图
- 底部：预警项目列表
- 汇报中心：一键生成多版本报告（董事会版/公众版/政府版）
- AI 助手：全量问答 + 下钻 + 汇报生成

### L3 业务工作台
- 项目列表（含 SQI 评分和数据回收告警）
- SQI 评估中心（排名/趋势/数据缺口/采集管理）
- AI 助手（本线问答 + 方案参考 + 案例推荐）

### L2 内部门户
- 公开案例浏览、SOP 库、SQI 概览（脱敏版）、AI 问答（公开版）

### L1 外部接入
- 主推 MCP 协议（客户用自己的 AI 工具直连）
- 备选轻量 Web Portal

1. **数据管理**：数据源接入/联邦网关/质量监控/捐赠数据回收

6. **系统管理**：模型管理/内容审核/审计日志

## 七、善擎 ↔ Nexus 的关联分析

### 共同点
| 维度 | 善擎 | Nexus |
|------|------|-------|
| 核心问题 | 各业务线数据分散，管理者看不到全局 | 各团队信息分散，组织看不到彼此在做什么 |
| 解法思路 | 数据统一层 + 联邦查询 | 异步结晶 + 信息聚合层 |
| AI 角色 | 权限感知的智能检索/评估/预警 | 连接/翻译/预警/留存（上次讨论的重新定义） |
| 权限模型 | L1-L4 四级 | 待设计（管理者 vs 员工 vs 组织） |
| 管理者视图 | VP 驾驶舱（SQI 热力图/预警/一键汇报） | 管理驾驶舱（组织脉搏/静默预警/信号响应） |
| 冷启动策略 | B 端倒逼 A 端补数据 | 管理者先行 + 场景框定 |

### 善擎中可复用到 Nexus 的设计模式
1. **权限感知的 AI 输出**：同一信息根据角色展示不同深度——Nexus 也需要
2. **异常预警 > 总结**：善擎的 AI 不是"总结数据"而是"检测异常信号"——与 Nexus AI 重新定位一致
3. **数据完整度监控**：善擎会告诉你"哪些项目的 SQI 还缺什么数据"——Nexus 可以告诉你"哪些团队/项目的透明度还缺什么"
4. **联邦查询不强制迁移**：先做查询层统一，各库不动——Nexus 也应该先聚合现有工具（Odin/WeThink/企微）的信息，而不是要求大家搬家
5. **A/B 双循环**：善擎用"外部需求倒逼内部数据治理"——Nexus 可以用"管理者查看需求倒逼团队输入"

### 善擎中需要避免的
1. 善擎是**数据驱动**的（结构化数据 → SQI 评分），Nexus 是**内容驱动**的（非结构化结晶 → 组织透明），不能照搬善擎的"评分卡"思维
2. 善擎有强行政推力（SQI 评估写入项目验收），Nexus 的推力更弱，需要更多产品设计来降低摩擦
