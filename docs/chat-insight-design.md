# Nexus「AI 洞察对话」设计方案

> 场景：Chat Insight — 管理者通过对话获取组织级 AI 洞察
> 版本：v1.0 / 2026-05-15

---

## 一、这个界面在 Nexus 里的位置

Nexus 的定位是 **SSV 组织层面的异步信息共享、沉淀与发现平台**。它不在一线生产环节中——Odin 管项目执行，WeThink 管讨论决策，企微管日常沟通——Nexus 是这些工具的**下游聚合层**，解决的核心问题是：

> **「让组织知道彼此在做什么」**

Chat Insight 是 Nexus 的 **AI 主动发现入口**。它不是一个通用聊天机器人，而是一个**场景框定的、组织级的信息断裂检测器**。

### 与第一场景的关系

脑爆会共识的第一场景是「目标公示 + 项目进展」——各团队公示 Q 目标，下挂支撑项目，管理者提供方向反馈。Chat Insight 就是这个场景的 **AI 增值层**：

```
各团队发布进展（输入层）
      ↓
AI 跨团队扫描 + 关联 + 检测（AI 层）
      ↓
Chat Insight 呈现洞察（输出层）← 本方案
      ↓
管理者操作（发起讨论 / @负责人 / 追问）
```

没有 Chat Insight，Nexus 只是一个「大家把周报贴上去」的工具——有了它，Nexus 才能兑现「AI 帮组织看到人看不到的东西」这个核心承诺。

## 二、设计原则（来自 Nexus 四条核心理念）

### 原则 1：发布必须抵消已有工作

Chat Insight 的输入**不需要任何人额外写东西**。AI 基于各团队已有的项目进展发布来生成洞察——你发了项目进展，AI 自动帮你做跨团队关联，不额外增加一个字的输入负担。

**设计体现**：界面上不出现「请输入你的本周工作」，只出现「本周有哪些值得关注的？」——AI 主动给你看，不是你喂给 AI。

### 原则 2：管理者先行

Chat Insight 的第一批用户就是 Catherine / XD 类管理者。界面设计围绕管理者的消费模式：**扫描式、结论先行、可操作**。不是给员工看的知识库，是给管理者看的组织雷达。

**设计体现**：卡片式洞察，3 秒看完结论；操作按钮直接挂在洞察下面，不需要跳转。

### 原则 3：场景要框定

AI 不是空白画布式的「你问什么我答什么」。Chat Insight 框定了两类洞察场景：
- **协同机会**：多个团队在做相关工作但没有交叉
- **信息断裂**：上下游依赖中出现了信息流转中断

后续可扩展（风险预警、目标偏离、资源冲突），但 V1 只做这两类——足够有价值，又不会因为「AI 什么都能说」而变得不可控。

**设计体现**：每条洞察有明确的类型图标和分类标签，不是一段模糊的分析文字。

### 原则 4：输入要极低摩擦

管理者消费洞察的摩擦也要极低。不需要读完一篇 200 字的分析才能决定「这事要不要管」。

**设计体现**：这正是本方案要解决的核心问题——两个方案对比的就是「信息消费摩擦」的高低。

## 三、两个方案对比

### 方案 A · 结构化卡片（推荐）

AI 的自然语言输出被拆解为**结构化洞察卡片**，每张卡片四层：

| 层次 | 元素 | 传递方式 |
|------|------|---------|
| 类型识别 | 左侧图标（协同=交汇圆环 / 风险=感叹号）+ 色块 | 视觉，不用读字 |
| 核心结论 | 加粗标题一句话（「3个团队在做同一件事」） | 3 秒扫完 |
| 结构化标签 | 彩色药丸（紫=项目关联 / 红=风险 / 绿=已完成） | 状态靠色彩，不靠文字 |
| 补充说明 | 灰色小字一行 | 给想看细节的人 |

**文字量**：~50 字 / 条洞察。

### 方案 B · 全文字

AI 用完整自然语言段落描述洞察，紫色高亮块标注重点。

**文字量**：~150 字 / 条洞察。

### 对比

| 维度 | A 卡片 | B 全文字 |
|------|--------|---------|
| 消费时间 | 3-5 秒 / 条 | 15-20 秒 / 条 |
| 适合场景 | 早上花 2 分钟扫一眼 | 坐下来认真理解上下文 |
| 截图传播 | 一眼看懂 | 需要阅读 |
| AI 感知 | 「AI 帮我整理好了」 | 「AI 帮我写了一段话」 |
| 扩展到 5+ 条洞察 | 卡片列表，毫无压力 | 文字墙，不可能扫完 |
| 因果推理链 | 被压缩，需点击展开 | 完整保留 |

## 四、为什么推荐方案 A

### 4.1 匹配管理者的消费模式

Catherine 的使用场景是「早上看两分钟，判断今天要不要介入什么事」。这是**扫描式决策**，不是**深度阅读**。方案 A 的卡片天然支持扫描：类型→结论→状态→操作，四步完成。

方案 B 的段落文字要求线性阅读——这不是管理者打开 Nexus 时的心理预期。

### 4.2 AI 密度的「感知」问题

方案 A 和 B 背后的 AI 能力完全一样。但用户感知截然不同：

- 方案 B 像「AI 写了一封邮件给你」——用户下意识把它当文字内容来评判质量
- 方案 A 像「AI 帮你做了一个仪表盘」——用户感受到的是 AI 的**结构化理解能力**

Nexus 的难题之一是「AI 总结只是压缩没有增量价值」。方案 A 通过结构化呈现，让用户直观感受到 AI 不是在「缩写」，而是在「理解 + 分类 + 判断严重度」。

### 4.3 解决「发了没回报」的恶性循环

Nexus 当前最大的冷启动障碍是：员工发了内容，感觉没有人看、没有回报。

Chat Insight 的存在本身就是回报——「你发的项目进展，AI 帮你关联到了其他团队」「你停更 14 天，AI 替你发现了卡点已解除」。但这种回报**必须被快速感知**，不能埋在一段 200 字的段落里。

方案 A 的标签（`相关项目：用户画像标签` / `14天未更新` / `评审已完成`）在视觉上就是对输入者的反馈闭环——你的发布被 AI 读懂了，而且产生了跨团队价值。

### 4.4 为后续 AI 能力预留结构

卡片结构天然支持 Nexus 后续的 AI 演进：

| 能力 | 卡片如何承载 |
|------|------------|
| 洞察分级 | 卡片左上角加紧急度标记（🔴🟡🟢） |
| 操作闭环 | 卡片内嵌「发起跨团队讨论」「@刘强」 |
| 状态追踪 | 卡片状态可变（「已发起讨论」→ 绿✓） |
| 权限感知（借鉴善擎 L1-L4） | 同一洞察，管理者卡片显示完整团队名 + 负责人，员工卡片只显示「3 个团队有协同机会」 |
| MCP 接入（借鉴善擎对外协议） | 会议记录 / OKR 自动灌入后，AI 洞察的数据源更丰富，卡片标注来源 |

## 五、AI 在这个界面里具体做了什么

这不是一个「展示信息」的界面。AI 的工作链路：

```
信息采集 → 跨源关联 → 模式识别 → 严重度判断 → 结构化输出 → 操作建议
```

以本周两条洞察为例：

### 洞察 1：跨团队协同机会

| 步骤 | AI 做了什么 | 为什么人做不到 |
|------|-----------|--------------|
| 采集 | 扫描张明、林敏、王芳三个团队本周的项目进展发布 | 管理者没时间看每个团队的每条更新 |
| 关联 | 发现三个团队都提到「用户画像标签」相关工作 | 人不会同时记住 20 个团队各自在做什么 |
| 理解 | 判断三个团队从不同层面切入（受助人画像 / 标签架构 / 捐赠者聚类） | 需要理解每个团队的具体上下文才能判断 |
| 判定 | 归类为「协同机会」而非「正常并行」 | 需要领域知识判断「这三件事本质上是一个底层问题」 |

### 洞察 2：信息断裂检测

| 步骤 | AI 做了什么 | 为什么人做不到 |
|------|-----------|--------------|
| 时序监控 | 发现刘强项目组 14 天未更新 | 人不会盯着每个项目的更新频率 |
| 跨源比对 | 发现赵鹏安全评审已于 5/9 完成 | 两个不相关团队的信息，人不会主动交叉检查 |
| 因果推理 | 判断「等待评审」这个卡点已经可以解除 | 需要同时知道上游结论 + 下游状态才能推理 |
| 输出建议 | 生成「追踪乡村教育卡点」操作 | AI 不只是报信，还要提供下一步 |

这就是 Nexus AI 的核心价值：**不是总结已知信息，而是发现跨团队的、人看不到的关联和断裂**。这也是 Nexus 区别于周报/OKR 工具的本质差异——周报让你知道别人写了什么，Nexus 让你知道**别人之间有什么关系你不知道**。

## 六、与 Nexus 已有问题的对应关系

| Nexus 的问题 | Chat Insight 怎么回应 |
|-------------|---------------------|
| 没人用 → 不在生产链路中 | AI 洞察是**被动消费**的，管理者打开就能看到，不需要主动操作 |
| 不知道发什么（空白画布焦虑） | Chat Insight 不要求用户发布任何东西，它消费的是已有的项目进展 |
| 不敢发（社交压力） | 管理者是第一消费者，管理者先看 → 降低员工「发了会怎样」的焦虑 |
| 发了没回报 | AI 洞察本身就是对发布内容的回报——你的内容被 AI 读懂并产生了跨团队价值 |
| AI 总结「没用」 | 不做总结，做**检测**——协同机会检测、信息断裂检测、风险预警 |
| 越没人用→越没内容→越没人来 | Chat Insight 给了管理者一个「每天打开 Nexus 看两分钟」的理由，打破恶性循环 |

## 七、演进路径

### V1（当前）
- 两类洞察：协同机会 + 信息断裂
- 输入源：各团队在 Nexus 上的项目进展发布
- 消费者：管理者（Catherine / XD）

### V2
- 新增洞察类型：目标偏离预警、资源冲突检测
- 输入源新增：MCP 接入会议记录 + OKR（优先级最高的两个 MCP 对接）
- 点击卡片 → 展开完整上下文（方案 B 的内容作为展开态）
- 操作闭环：卡片内可直接「@负责人」「发起跨团队讨论」

### V3
- 权限感知输出（借鉴善擎 L1-L4）：管理者 vs 员工看到不同深度的洞察
- 洞察积累 → 组织记忆时间线，可追溯模式变化
- AI 主动推送（不需要用户问，合适时机直接出现在消息流中）

|------|------|------|
| 协同 / 关联 | `#7C3AED` violet | 协同图标、项目标签 |

| 卡片背景 | `#F4F3F0` | |
| 气泡背景 | `#FFFFFF` | |

```
┌──────────────────────────────────────┐
```
